# מדריך הזנת בוט השירות של Zomee

המדריך מתרגם את האפיון שקיבלנו למבנה של בוט השירות במערכת. מומלץ לבנות תחילה את כל השלבים, ורק לאחר מכן לחבר ביניהם ולהפעיל את הבוט.

## 1. הגדרות כלליות

- שם פנימי: `בוט שירות Zomee`
- משפט טריגר מומלץ: `שירות לקוחות`
- תפריט ראשי: `main`
- תוקף שיחה: `60` דקות
- תגובה לבחירה לא מוכרת: `לא הצלחתי לזהות את הבחירה. בחרי אחת מהאפשרויות שמופיעות בתפריט.`
- מעבר לנציגה מכל שלב: להפעיל ולהזין את מספר הנציגה.

שמות משתנים נכתבים באנגלית, ללא רווחים. אפשר לשלב ערך שנשמר בתוך הודעה באמצעות `{{variable_name}}`.

## 2. סדר בנייה מומלץ

1. צרו את כל שלבי ההודעה וההמלצה הסופיים.
2. צרו את שלבי קליטת המידע.
3. צרו את תפריטי המשנה.
4. צרו את שלב התנאי של שאלון ההתאמה.
5. צרו בסוף את התפריט הראשי וחברו אליו את כל המסלולים.
6. הריצו “בדיקת תקינות”, שמרו ורק אז הפעילו.

## 3. התפריט הראשי

צרו שלב מסוג “תפריט עם בחירות” בשם `main` עם הודעת הפתיחה מהאפיון ושבע האפשרויות הבאות:

| כותרת קצרה ב-WhatsApp | יעד |
| --- | --- |
| התאמת משאבה | `pump-fit-q1` |
| התאמת מידה | `size-guide` |
| משלוחים | `shipping-menu` |
| החזרת מוצרים | `returns-policy` |
| תקלות במשאבה | `support-menu` |
| שימוש בקופון | `coupon-info` |
| יועצת הנקה | `human-handoff` |

הכותרות קוצרו בכוונה כדי להתאים למגבלת הכותרת של רשימות WhatsApp. את הניסוח המלא מציגים בתוך השלב.

## 4. שאלון התאמת משאבה

### `pump-fit-q1` - מה את מחפשת?

סוג: תפריט.

- `משאבה לבישה בחזייה` → `pump-fit-q2`. שמירת משתנה: `pump_style=wearable`.
- `משאבה עם קונוסים` → `recommend-2z`. שמירת משתנה: `pump_style=cones`.

### `pump-fit-q2` - מה הצורך שלך?

- `חימום לשחרור רפלקס` → `pump-fit-q3`. שמירה: `pump_need=warming`.
- `מיכל נפרד` → `pump-fit-q3`. שמירה: `pump_need=separate`.

### `pump-fit-q3` - מה מידת הקאפ?

- `קטנה–בינונית` → `pump-fit-q4`. שמירה: `cup_size=small_medium`.
- `גדולה` → `pump-fit-q4`. שמירה: `cup_size=large`.

### `pump-fit-q4` - כמה מצבי שאיבה חשובים לך?

- `כמה שיותר מצבים` → `pump-fit-result`. שמירה: `pump_modes=many`.
- `פחות חשוב` → `pump-fit-result`. שמירה: `pump_modes=basic`.

### `pump-fit-result` - חישוב ההמלצה

סוג: תנאי לפי תשובות. כל התנאים בתוך כלל מחוברים ב-AND. הכלל הראשון שמתאים נבחר.

האפיון המקורי אינו מגדיר כיצד מכריעים כאשר תשובות שונות מצביעות על דגמים שונים. עד לקבלת הכרעה מ-Zomee, אפשר להשתמש בכלל “רוב של שתי תשובות”:

| כלל | תנאים | יעד |
| --- | --- | --- |
| 1W-1 | `pump_need=warming`, `cup_size=small_medium`, `pump_modes=many` | `recommend-1w` |
| 1W-2 | `pump_need=warming`, `cup_size=small_medium`, `pump_modes=basic` | `recommend-1w` |
| 1W-3 | `pump_need=warming`, `cup_size=large`, `pump_modes=many` | `recommend-1w` |
| FIT-1 | `pump_need=warming`, `cup_size=large`, `pump_modes=basic` | `recommend-fit` |
| 1W-4 | `pump_need=separate`, `cup_size=small_medium`, `pump_modes=many` | `recommend-1w` |
| FIT-2 | `pump_need=separate`, `cup_size=small_medium`, `pump_modes=basic` | `recommend-fit` |
| FIT-3 | `pump_need=separate`, `cup_size=large`, `pump_modes=many` | `recommend-fit` |
| FIT-4 | `pump_need=separate`, `cup_size=large`, `pump_modes=basic` | `recommend-fit` |

יעד ברירת מחדל: `human-handoff`.

### שלבי ההמלצה

צרו שלושה שלבי הודעה: `recommend-1w`, `recommend-fit`, `recommend-2z`. בכל שלב הזינו את נוסח ההמלצה והקישור המתאים.

בכל אחד משלבי ההמלצה הגדירו:

- הודעת המשך אחרי: `10` דקות.
- מעבר לשלב: `purchase-check`.
- השאירו את הודעת הטקסט הפשוטה ריקה, מפני שהיעד עצמו מכיל את ההודעה והאפשרויות.

### `purchase-check`

סוג: תפריט.

- `ביצעתי רכישה` → `purchase-thanks`.
- `רוצה להתייעץ` → `human-handoff`.

ההודעה המתוזמנת מתבטלת אוטומטית אם הלקוחה שולחת הודעה לפני שעברו עשר דקות. אין כאן זיהוי רכישה אוטומטי באתר.

## 5. התאמת מידה

`size-guide` הוא שלב הודעה עם נוסח ההסבר והקישור למדריך התאמת המידה.

## 6. משלוחים

`shipping-menu` הוא תפריט עם שתי אפשרויות:

- `מעקב אחר משלוח` → `shipping-track`, הודעה עם הקישור ל-Cargo והסבר על מספר המעקב.
- `רכישה וקבלה היום` → `shipping-purchase`, הודעה עם נקודות המכירה, איסוף עצמי והקישור לאתר.

## 7. החזרת מוצרים

### `returns-policy`

סוג: תפריט. הציגו את מדיניות ההחזרה והוסיפו אפשרות `אני רוצה לבצע החזרה` → `return-order-input`.

### `return-order-input`

- סוג: קליטת מידע מהלקוח.
- סוג מידע: טקסט חופשי.
- שם משתנה: `order_number`.
- יעד: `return-photo-input`.
- שגיאה: `נא לשלוח את מספר ההזמנה.`

### `return-photo-input`

- סוג: קליטת מידע מהלקוח.
- סוג מידע: תמונה.
- שם משתנה: `product_photo`.
- יעד: `return-confirmation`.
- שגיאה: `נא לשלוח תמונה של המוצרים כשהם סגורים.`

### `return-confirmation`

הודעה לדוגמה: `תודה, קיבלנו את פרטי הזמנה {{order_number}} ואת התמונה. נציגה תחזור אלייך להמשך הטיפול.`

פרטי התשובות והמדיה יופיעו באזור “מידע שנאסף בשיחות”. התמונה עצמה נשארת זמינה בשיחת WhatsApp; המערכת שומרת את פרטי הודעת המדיה לצורך זיהוי הפנייה.

## 8. קופונים

`coupon-info` הוא שלב הודעה עם ההסבר הנפרד למחשב ולמובייל.

## 9. תקלות ותפעול

צרו `support-menu` עם תשע האפשרויות מהאפיון. תשע אפשרויות נכנסות ברשימת WhatsApp אחת.

יעדים מומלצים:

- `charge-issue-menu`
- `not-turning-on`
- `weak-suction`
- `leak`
- `one-side`
- `heating-symbol`
- `stops-mid-pump`
- `baby-buddha-compatibility`
- `collection-cups-compatibility`

את התקלה “המשאבה לא נטענת” מומלץ לפצל לתפריט נוסף לפי דגם: `1W`, `Fit`, `2Z`. כך כל הודעה נשארת קצרה וקריאה. טקסט ארוך במיוחד יש לפצל באמצעות תפריט עם אפשרות `המשך` לשלב נוסף.

## 10. מעבר לנציגה

`human-handoff` הוא שלב מסוג “מעבר לנציג”. הזינו בו את ההודעה ואת מספר ה-WhatsApp של הנציגה. אפשר גם להפעיל “מעבר לנציג מכל שלב” בהגדרות הכלליות.

## 11. בדיקות לפני הפעלה

- ודאו שלכל אפשרות, שלב קליטת מידע, כלל תנאי והודעה מתוזמנת יש יעד קיים.
- ודאו ששמות המשתנים זהים לחלוטין בכל המקומות.
- בדקו לפחות מסלול אחד לכל המלצת משאבה.
- בדקו החזרה עם מספר הזמנה ותמונה אמיתית.
- בדקו שהודעת עשר הדקות מתבטלת כאשר מגיבים לפני הזמן.
- בדקו את כל תשע התקלות ואת כפתורי החזרה לתפריט.
- הפעילו את הבוט רק לאחר שבדיקת התקינות מסתיימת בהצלחה.
